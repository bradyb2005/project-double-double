# Project Double Double

COSC 310 Final Project.
Version: M1 - First Vertical Slice

### Required Python Version

* `3.12+`

### Quick start (one command)

```bash
git clone https://github.com/bradyb2005/project-double-double.git
cd project-double-double
./start.sh
```

`start.sh` installs anything missing (Python 3.12+, Node 20.19+, a `.venv`, the backend and frontend dependencies), then starts both servers:

 - Backend at http://127.0.0.1:8000 (API docs at `/docs`)
 - Frontend at http://localhost:5173

Press Ctrl+C to stop both. Use `./start.sh --setup-only` to install without starting. Works on macOS, Linux and Windows (Git Bash / WSL).

### Setup Instructions (manual)

Prerequisites: Python 3.12+ and Node.js 20.19+ (with npm), plus Git.

1. Clone the repo:

   ```bash
   git clone https://github.com/bradyb2005/project-double-double.git
   cd project-double-double
   ```
2. Create the virtual environment (from the repo root)

   macOS / Linux:
   ```bash
   python3 -m venv .venv
   ```

   Windows (PowerShell or Command Prompt):
   ```powershell
   py -m venv .venv
   ```
3. Activate it

   macOS / Linux (bash / zsh):
   ```bash
   source .venv/bin/activate
   ```

   Windows PowerShell:
   ```powershell
   .venv\Scripts\Activate.ps1
   ```
   If PowerShell blocks the script, run `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` once and retry.

   Windows Command Prompt:
   ```bat
   .venv\Scripts\activate.bat
   ```

   Windows Git Bash:
   ```bash
   source .venv/Scripts/activate
   ```
4. Install backend dependencies (same command on every platform)

   ```bash
   pip install -r backend/app/requirements.txt
   ```
5. Install frontend dependencies (same command on every platform)

   ```bash
   cd frontend
   npm install
   cd ..
   ```

### How to start the application

Use two terminals, both starting at the repo root. Activate the venv (step 3 above) in the backend terminal.

**Terminal 1, backend (run in the `backend/` directory):**
```bash
cd backend
uvicorn app.main:app --reload
```

**Terminal 2, frontend (run in the `frontend/` directory):**
```bash
cd frontend
npm run dev
```

The frontend is at http://localhost:5173 and proxies `/api/*` to the backend, so start the backend first.

### API

Interactive docs (generated by FastAPI) are at http://127.0.0.1:8000/docs, and the OpenAPI schema is at http://127.0.0.1:8000/openapi.json.

| Method | Path | Purpose | Success | Errors |
|---|---|---|---|---|
| GET | `/health` | Health check | 200 | |
| GET | `/restaurants` | List restaurants, with optional `search`, `cuisine`, `city`, `province` and `rating` (minimum) filters | 200 | 400 |
| POST | `/restaurants` | Create a restaurant | 201 | 400 |
| GET | `/restaurants/names` | List restaurant names | 200 | 400 |
| GET | `/restaurants/{id}` | Restaurant details | 200 | 404 |
| PUT | `/restaurants/update/{restaurant_id}` | Update a restaurant (partial) | 200 | 404 |
| GET | `/restaurants/{restaurant_id}/menu` | View a restaurant's menu | 200 | 404 |
| POST | `/restaurants/{restaurant_id}/menu` | Add a menu item | 201 | 400 |
| PUT | `/restaurants/{restaurant_id}/menu/{item_id}` | Update a menu item (partial) | 200 | 400 |

Errors are returned as `{"detail": "<reason>"}`. Invalid request bodies or path values return 422 from FastAPI.

**Vertical slice (customer flow):** list restaurants → search / filter → restaurant details → menu → menu items.

**Location of representative data:**
Stored inside `backend/data/restaurants.json`. Each restaurant embeds its own `menu` list, and IDs are assigned as the current maximum + 1.

### Architecture

Every request goes route → service → repository → JSON file:

 - `api/routes/` takes the HTTP request, validates it with Pydantic models and turns errors into HTTP responses.
 - `services/` holds the business logic (validation rules, filtering, ID assignment).
 - `repositories/` is the only layer that reads and writes `data/restaurants.json` (writes go to a temp file that is then swapped in).
 - `schemas/` holds the Pydantic request and response models.

### Frontend

React + Vite app in `frontend/` that talks to the REST API (Vite proxies `/api/*` to the backend). It lets a customer browse restaurants, view details and menus, and lets a restaurant owner create and edit restaurants and menu items. See `frontend/README.md` for the pages.

### How to run tests

Run in the `backend/` directory (with the venv active):

```bash
cd backend
python -m pytest
```

The service and route tests use isolated temporary data files (see `backend/tests/conftest.py`), so they don't modify `backend/data/restaurants.json`.

### Continuous integration

`.github/workflows/ci.yml` runs on every push to `main` and every pull request. It installs the backend dependencies in a clean Ubuntu environment and runs `pytest`, and it also lints and builds the frontend.
